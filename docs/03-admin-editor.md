# Админка: интерфейс «добавить проект»

Собственный UI внутри frontend-приложения (маршруты `/admin/*`), работает с API из [02-data-model.md](02-data-model.md). Это Phase 3 роадмапа; до неё контент вносится через стандартную Django-админку (`api.manshoo.ru/django-admin/`) — она бесплатно есть с первого дня и остаётся страховкой навсегда.

Замечание для Phase 3: админка живёт на manshoo.ru, API — на api.manshoo.ru. Это **same-site** (один registrable domain), поэтому сессионные куки Django работают без SameSite-танцев; понадобится только CORS (`Access-Control-Allow-Origin: https://manshoo.ru` + credentials) и `CSRF_TRUSTED_ORIGINS` (уже настроен).

## Маршруты

| Маршрут | Что |
|---|---|
| `/admin/login` | Форма входа (логин/пароль → `POST /api/auth/login`) |
| `/admin` | Дашборд: список проектов + быстрые действия |
| `/admin/projects/new` | Создание проекта |
| `/admin/projects/[id]` | Редактирование |
| `/admin/profile` | Редактирование блока «обо мне» |

Весь раздел: CSR (`export const ssr = false` для группы маршрутов), `noindex` в meta + `Disallow: /admin` в robots.txt, guard-редирект на login по `GET /api/auth/me`.

## Форма проекта

Порядок полей = порядок заполнения мыслей: «что это» → «как это было» → «чем горжусь» → «оформление».

1. **Что это:** title, tagline, slug (автогенерация из title транслитом, редактируемый), project_type, status.
2. **Резюме-контекст:** role, org, period_start, period_end (чекбокс «по настоящее время»).
3. **Суть:** description_md — textarea с live-превью (рендер тем же Markdown-пайплайном, что на сайте: одна картинка мира); stack — tag-input (Enter добавляет, автодополнение из уже использованных тегов); highlights — динамический список строк (добавить/удалить/перетащить).
4. **Ссылки и вид:** links (live/repo/case), cover — drag&drop загрузка с превью (`POST .../cover`), uptime_monitor_slug — select из `GET` статусов чекера + пустое значение.
5. **Публикация:** is_published, is_featured, sort_order; кнопки **Сохранить**, **Предпросмотр** (открывает `/projects/<slug>?preview=1` в новой вкладке — SSR-страница отдаёт черновик по сессии), **Удалить** (с confirm).

## Как сделано (Phase 3, 2026-07-30)

Отличия от первоначального плана — с причинами:

- **Аутентификация**: сессия Django + CSRF-токен из `GET /api/auth/csrf`. Куку csrf с manshoo.ru не прочитать (её ставит api.manshoo.ru), поэтому токен отдаётся эндпоинтом и уходит заголовком `X-CSRFToken`. **Django ротирует токен при `login()`** — админка перезапрашивает его сразу после входа (иначе первая же мутация ловит 403).
- **CSRF в django-ninja 1.6**: параметра `NinjaAPI(csrf=True)` больше нет. Небезопасные методы под `django_auth` проверяются автоматически (cookie-аутентификация ninja), а логин защищён вручную через `check_csrf` — Django-декораторы (`csrf_protect`, `ensure_csrf_cookie`) поверх операций ninja не работают: они ждут `HttpResponse`, а операция возвращает dict.
- **Предпросмотр черновиков**: `SESSION_COOKIE_DOMAIN=.manshoo.ru` делает сессию общей для сайта и API, поэтому SSR-страница `/projects/<slug>?preview=1` передаёт куку в api и получает черновик. Страница помечается `noindex` и показывает баннер предпросмотра.
- **Slug**: транслитерация кириллицы (`content/slugs.py`), «Мой проект» → `moy-proekt`; коллизии получают суффикс `-2`. Первая версия оставляла кириллицу в URL — некрасиво в ссылках.
- **Обложки**: Pillow пересохраняет загруженное в **WebP** (≤1600 px, EXIF отброшен) — это и валидация «действительно ли это картинка», и вес страницы.
- **Структура фронтенда**: публичные страницы и админка разведены route-группами `(site)` и `admin` — у админки свой минимальный layout без шапки сайта, общие токены темы вынесены в `src/app.css`.

## MVP-срезы (осознанные упрощения)

- Markdown-редактор = textarea + превью-панель по кнопке; никаких WYSIWYG.
- Одна обложка на проект; галерея — бэклог.
- Сортировка — числовое поле `sort_order`; drag&drop списка — бэклог. Порядок «ключевых фишек» меняется стрелками ↑↓.
- Никакой ролевой модели: один пользователь-владелец (`is_staff`).
- Загрузка обложки доступна после первого сохранения проекта (нужен id).
- TS-типы контракта по-прежнему написаны руками — генерация из OpenAPI не понадобилась: контракт мал и меняется вместе с формой.

## Безопасность

- Сессия Django: HttpOnly, `SameSite=Lax`, `Secure`, домен `.manshoo.ru`; CSRF-токен на мутациях.
- Rate limit на `/api/auth/login`: 5 неудачных попыток в минуту с IP (счётчик в кэше; успешный вход его сбрасывает). За nginx IP берётся из `X-Forwarded-For`.
- Вход только для `is_staff` — обычный пользователь в админку не попадёт, даже если появится.
- Upload: лимит 5 МБ, пересохранение через Pillow (отрезает EXIF и «полиморфные» файлы), `client_max_body_size 10m` на nginx.
- CORS: разрешён единственный origin — `https://manshoo.ru`, с credentials.
- `/django-admin` — оставлен как страховка; basic auth на прокси **не настроен** (требует sudo-захода на VPS), см. открытый пункт в роадмапе.

## Критерий готовности фазы

Полный цикл без касания Django-админки: залогиниться → создать проект с обложкой → предпросмотреть черновик → опубликовать → увидеть на главной; отредактировать профиль.
