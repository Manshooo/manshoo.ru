# SEO-стратегия

Архитектурная основа: публичные страницы рендерятся сервером ([ADR-003](decisions/ADR-003-rendering-ssr.md)) — контент виден краулерам без JS. Аудитория русскоязычная, поэтому **Яндекс равноправен с Google** во всех пунктах.

## База (Phase 2, вместе с первым деплоем)

- [ ] Уникальные `<title>` и `<meta name="description">` на каждой странице (у проекта — из title/tagline; у главной — из `Profile.meta_description`).
- [ ] `<link rel="canonical">`; единый хост (www → без www, 301), https-редирект.
- [ ] Семантика: один `<h1>` на страницу, `<main>/<nav>/<article>`, alt у изображений.
- [ ] `sitemap.xml` — динамический endpoint во frontend, тянет slugs + `updated_at` из API.
- [ ] `robots.txt`: `Disallow: /admin`, `/api`, `/django-admin`; ссылка на sitemap.
- [ ] Открыть страницы 404 (реальный код ответа, не SPA-заглушка).
- [ ] Open Graph + Twitter Card: пока одна дефолтная OG-картинка на сайт.
- [ ] Регистрация: Google Search Console + Яндекс.Вебмастер, отправить sitemap в оба.

## Структурированные данные — сделано в Phase 4

- [x] Главная: `Person` (имя, описание, навыки, sameAs из соцсетей) + `WebSite`, связанные через `@id`.
- [x] Страница проекта: `SoftwareSourceCode` с `codeRepository`, если у проекта есть репозиторий, иначе `CreativeWork`; плюс `BreadcrumbList`.
- [ ] Проверка через Rich Results Test и валидатор Яндекса (за владельцем).

Реализация — `src/lib/jsonld.ts` и компонент `JsonLd.svelte` (экранирует `<`, чтобы содержимое не могло закрыть тег script).

## Производительность = SEO (Phase 2 базово, Phase 4 добивка)

- [ ] Шрифты: self-hosted woff2, `preload`, `font-display: swap` (никаких Google Fonts с CDN — и быстрее, и в РФ надёжнее).
- [ ] Изображения: web-форматы (webp/avif), явные `width/height` (нет CLS), `loading="lazy"` ниже фолда; обложки ужимаются при загрузке в админке.
- [ ] JS-бюджет: Svelte и так компактен; следить, чтобы публичные страницы не тянули админочный код (раздельные route-группы).
- [ ] Метрика: Lighthouse Performance ≥ 95, SEO ≥ 95 на мобильном профиле. В CI — Lighthouse CI на PR во frontend (Phase 4).

## OG-картинки проектов — сделано в Phase 4

Выбран Pillow-endpoint в api (`GET /api/projects/{slug}/og.png`): 1200×630, заголовок + подзаголовок + стек + имя автора на тёмной подложке. Кэш на диске, ключ включает `updated_at` — правка проекта автоматически перерисовывает картинку, старые версии подчищаются. Черновикам картинка не выдаётся (404).

Почему не satori во frontend: он тянет в SSR-процесс WASM-рендер и шрифты, а у api уже есть Pillow и место под медиа. Шрифт — DejaVu из образа (кириллица).

## Контентное SEO (бэклог, но именно оно даст трафик)

Портфолио само по себе низкочастотно (брендовые запросы «имя фамилия»). Реальный поисковый трафик приносит **блог/кейсы**: «как я делал X», разборы технологий из stack'а проектов. См. [07-ideas.md](07-ideas.md) — блог там идея №1 именно по этой причине. При появлении EN-версии — `hreflang`.

## Чего не делаем

Никаких «SEO-трюков»: скрытых текстов, накрутки ключевых слов, каталогов ссылок. Максимум пользы — от технической чистоты + контента.
