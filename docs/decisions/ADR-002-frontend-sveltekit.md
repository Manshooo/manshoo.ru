# ADR-002: Фронтенд — SvelteKit (Svelte 5, TypeScript)

**Status:** Accepted
**Date:** 2026-07-30
**Deciders:** Yanislav Pichugin

## Context

Требования: TypeScript; фреймворк **не React** (явное желание попробовать другое); SSR/prerender для SEO; в том же приложении — интерактивная админка (формы, загрузка файлов, превью). Одно приложение должно уметь и «контентные» страницы, и «app»-раздел.

## Decision

**SvelteKit** (Svelte 5 с runes, TypeScript, adapter-node в Docker). Таймбокс-страховка: если после спайка в 1 вечер (прототип главной) Svelte «не зайдёт» — откат на Nuxt без изменения остальной архитектуры (контракт с api тот же).

## Options Considered

### Option A: SvelteKit (Svelte 5)

| Dimension | Assessment |
|-----------|------------|
| Отличие от React | High — компилятор вместо VDOM, runes вместо hooks: настоящий «другой» опыт |
| SSR/SEO | High — SSR, prerender, гибрид на уровне маршрута из коробки |
| Размер бандла | High (маленький) — важно для Lighthouse |
| Экосистема | Med — меньше React/Vue, но для этого проекта хватает |

**Pros:** любимец разработчиков (годы лидерства в State of JS по удовлетворённости); file-based роутинг + form actions + load-функции покрывают и сайт, и админку; писать заметно меньше кода.
**Cons:** экосистема компонентов беднее; Svelte 5 runes — свежая ментальная модель (для целей обучения это плюс).

### Option B: Nuxt 3/4 (Vue)

| Dimension | Assessment |
|-----------|------------|
| Отличие от React | Med — композиция через composables идейно близка к hooks |
| SSR/SEO | High — Nitro, модули seo/image/sitemap готовые |
| Размер бандла | Med |
| Экосистема | High — крупнейшая среди «не-React» |

**Pros:** самый «безопасный» выбор, много готовых модулей.
**Cons:** по ощущению разработки ближе всего к React — слабее закрывает мотивацию «попробовать другое»; тяжелее рантайм.

### Option C: Astro (+ islands)

| Dimension | Assessment |
|-----------|------------|
| Отличие от React | High |
| SSR/SEO | Highest для чистого контента (ноль JS по умолчанию) |
| Fit к админке | Low — админка = «остров» на чужом фреймворке или отдельное приложение |
| Экосистема | Med |

**Pros:** лучший в классе для контентных сайтов.
**Cons:** центральная фича проекта — интерактивная админка — в Astro живёт хуже всего; получилось бы «Astro + всё равно какой-то фреймворк для островов», т.е. два инструмента вместо одного.

### Option D: Angular

Полноценный SSR есть, но фреймворк тяжёлый и enterprise-ориентированный; для лендинга-портфолио — несоразмерный инструмент. Отклонён без детальной проработки.

## Trade-off Analysis

Nuxt — надёжнее по экосистеме, SvelteKit — сильнее по «попробовать принципиально другое» и по лёгкости страниц (SEO/perf-бюджет). Поскольку компонентная база проекта маленькая (карточки, формы, markdown), дефицит экосистемы Svelte почти не бьёт по задаче, а выигрыш в обучении и бандле — реальный. Astro проигрывает из-за админки: цельное приложение важнее идеального рендера контента.

## Consequences

- Публичные страницы и админка живут в одном приложении с разными режимами рендера (route-группы `(site)` SSR / `(admin)` CSR).
- Учим Svelte 5 (runes) — закладывать чуть больше времени на первые компоненты.
- Компоненты пишем сами (дизайн минималистичный — это дёшево); никаких тяжёлых UI-китов.
- Ревизит: пункт «откат на Nuxt» действует только до конца Phase 2; дальше решение окончательное.
