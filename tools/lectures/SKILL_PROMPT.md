# Промпт для создания скилла `lecture-notes`

Как пользоваться: в Claude Code запустите `/skill-creator` (или скажите «создай скилл») и вставьте
всё, что ниже линии. Skill-creator задаст уточняющие вопросы, соберёт `SKILL.md` и прогонит
тестовые примеры.

---

Создай скилл **lecture-notes**. Он превращает сырую расшифровку лекции или видео в готовый к
публикации .md-файл для раздела `/lectures` сайта manshoo.ru и заполняет метаданные. Файл потом
загружается через админку (`/admin/lectures`), а API проверяет шапку. Поэтому результат должен
проходить проверку с первого раза.

## Когда срабатывать

Когда просят: «оформи транскрипцию», «сделай конспект лекции», «подготовь лекцию к публикации»,
«причеши расшифровку», «добавь метаданные к лекции»; когда пользователь даёт `*.draft.md` из
`tools/lectures/transcribe.py`, файл субтитров (.srt/.vtt) или сырой текст расшифровки.

## Входные данные

- Черновик `<slug>.draft.md` из `tools/lectures/transcribe.py`: шапка с пустыми обязательными
  полями, абзацы вида `[00:12:30] текст…` и метки `> **[Кадр 00:12:30]** (frames/0007.jpg)`.
- Рядом с черновиком `segments.json` (сегменты распознавания с таймкодами), `frames.json` и папка
  `frames/` с кадрами (слайды, доска).
- Либо .srt/.vtt, либо просто текст. Тогда кадров нет, и визуальную часть не придумывать.
- Сведения от пользователя: курс, лектор, дата, номер лекции, ссылка на видео, разрешение автора.

Источники правды о формате (прочитать перед работой):

- `docs/09-lectures.md` — схема полей, правила, права;
- `tools/lectures/example-lecture.md` — эталонный пример оформления.

## Два режима

Спроси, если не ясно из запроса.

1. **Транскрипция** (`kind: transcript`) — отредактированный текст лектора. Публикуется
   **только с разрешением автора**. Если пользователь не может назвать, где и как получено
   согласие (поле `permission`), не выдумывай его и не ставь заглушку. Объясни, почему без
   разрешения нельзя (полная транскрипция воспроизводит чужое произведение), и предложи режим
   «конспект» или остановиться.
2. **Конспект** (`kind: notes`) — свой текст по мотивам лекции. Разрешение не нужно, но это
   должен быть **действительно свой текст**: своя структура, свои формулировки, сжатие.
   Пересказ абзац за абзацем с заменой слов юридически остаётся переработкой чужого
   произведения. Проверка: нельзя восстановить из конспекта текст лекции почти дословно.
   Короткие цитаты лектора можно давать в кавычках. `author` — тот, кто составляет конспект
   (спросить у пользователя).

## Порядок работы

1. **Метаданные.** Собери, что можно, из черновика и запроса. Недостающие обязательные поля
   (`date`, `permission` для транскрипции, `author` для конспекта) спроси одним сообщением, а не
   по одному. Лектора, язык и лицензию можно не писать, если они такие же, как у курса.
2. **Кадры.** Открой каждый файл из меток `[Кадр …]` и посмотри изображение.
   - Слайд с содержанием → блок `> **[На слайде]:** …`; доска → `> **[На доске]:** …`. Перенеси
     текст, формулы в LaTeX (`$…$`, `$$…$$`), таблицы в Markdown. Схемы и графики опиши словами:
     что изображено и какой вывод из этого следует.
   - Кадр без информации (лицо лектора, пустой экран, переходный кадр) — метку удали.
   - Слайды используй и чтобы исправлять ошибки распознавания в терминах и формулах.
   - Изображения в файл не вставляй: на сайт загружается только текст.
3. **Текст.**
   - *Транскрипция:* убрать слова-паразиты («ну», «вот», «значит», «эээ»), фальстарты,
     повторы и оговорки, которые лектор сам исправил. Исправить ошибки распознавания по
     контексту и слайдам. Сохранить формулировки, порядок изложения и примеры лектора. Ничего
     не добавлять от себя, не «улучшать» объяснения, не дописывать пропущенные шаги
     доказательств. Устную речь в письменную переводить минимально: только чтобы предложение
     читалось.
   - Неразборчивое место → `[неразборчиво 00:44:02]`; сомнительный термин → `термин [?]`. Не
     угадывать молча.
   - Вопросы из зала → `**Вопрос из зала:** …`, ответ → `**Лектор:** …`. Имён студентов не
     писать: это персональные данные.
   - *Конспект:* определения, теоремы, ключевые шаги доказательств, примеры, выводы. Своими
     словами, сжато, со своей структурой. Свои пояснения допустимы, но явно отделены
     («Примечание составителя: …»).
4. **Структура.**
   - Разделы `## N. Название раздела [ЧЧ:ММ:СС]`: таймкод начала раздела в видео, по разделу
     на тему (обычно 4–10 на полуторачасовую лекцию). Построчные таймкоды из черновика убрать.
   - Подразделы `###` — при необходимости, без таймкодов.
   - Абзацы по 3–6 предложений. Формулы в LaTeX, код в блоках с языком.
   - Не ставить заголовок `#` в теле: название страницы берётся из `title`.
5. **Метаданные по итогам.**
   - `summary` — 1–2 предложения: о чём лекция и что в ней разобрано.
   - `topics` — 3–8 тем строчными буквами, как термины, а не как предложения.
   - `quality: edited`. `verified` ставит только человек, который сверил текст с видео:
     скилл так не делает никогда.
   - `updated` — сегодняшняя дата. `number` — номер лекции в курсе, если известен.
6. **Проверка перед выдачей** (по каждому пункту, вслух коротко):
   - шапка — валидный YAML; все обязательные поля из `docs/09-lectures.md` на месте; даты
     `ГГГГ-ММ-ДД`; `duration` в кавычках; `license` (если указана) из списка
     `CC-BY-4.0`, `CC-BY-SA-4.0`, `CC-BY-NC-4.0`, `CC0-1.0`;
   - для `transcript` есть `permission` и `source.url`; для `notes` есть `author`;
   - имя файла `NN-slug.md`: латиница a-z, цифры, дефис (оно станет адресом страницы);
   - в теле не осталось меток `[Кадр …]`, построчных таймкодов, HTML-комментариев черновика;
   - нет имён студентов; нет домыслов, которых не было в лекции (для транскрипции).
7. **Выдача.** Записать файл рядом с черновиком как `<NN-slug>.md`, черновик не трогать.
   Показать сводку: режим, сколько разделов, сколько кадров описано и сколько удалено,
   все места с `[неразборчиво]` и `[?]` списком с таймкодами, чтобы человек сверил их с
   видео. Напомнить: загрузка через `/admin/lectures`, лекция появится черновиком.
   Опубликовать её можно после проверки.

## Длинные лекции

Полуторачасовая лекция — это 10–15 тысяч слов. Работай по разделам: сначала по всему черновику
набросай план разделов с таймкодами, затем редактируй раздел за разделом. Веди глоссарий
терминов и обозначений, чтобы во всей лекции один и тот же термин писался одинаково.

## Чего скилл не делает

- Не загружает файл на сайт и не публикует (это делает человек в админке).
- Не выдумывает разрешение автора, дату, имя лектора.
- Не вставляет в файл кадры и картинки.
- Не ставит `quality: verified`.

## Тестовые примеры для skill-creator

1. Черновик транскрипции с тремя кадрами (слайд с формулой, слайд-таблица, кадр с лицом лектора)
   и разрешением в запросе → файл с `kind: transcript`, два блока `[На слайде]`, третий кадр
   удалён, формула в LaTeX, разделы с таймкодами.
2. Тот же черновик, но разрешения нет → скилл не пишет `permission`, объясняет причину и
   предлагает конспект; после согласия делает `kind: notes` с `author`.
3. Сырой .srt без кадров, с вопросом студента по имени → имя убрано, «Вопрос из зала»,
   визуальных блоков нет, неразборчивое место помечено таймкодом.
